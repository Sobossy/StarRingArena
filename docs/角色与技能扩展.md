# 角色与技能扩展

0.6.0补充：技能脚本的`@export`整数、小数和开关会自动显示在角色编辑页“技能数值”里；范围使用`@export_range`，中文标签在SkillCatalog.PARAMETER_NAMES登记。参数保存在技能槽的`parameters`字典，开局复制到独立实例。当前注册角色仅毁灭主和花火，详见[当前技能与数值说明](花火与技能数值.md)。

## 0.2.0 的角色库与技能模板

日常修改属性和图片可直接使用游戏内角色编辑页，见 [新版说明](角色编辑与多人对战.md)。用户角色存储为带版本 JSON，开局生成独立配置快照；原有 `.tres` 和 `start_battle` 双人接口仍可用于代码扩展。

让新技能出现在编辑页：在 `scripts/core/skill_catalog.gd` 的 `ITEMS` 注册唯一 ID、中文名称、类型（主动/被动/持续）和技能场景。角色通过 `skill_slots` 记录模板 ID、独立槽位 ID、蓄力/释放时长、移动开关和图片路径。

主动技能在冷却完成时调用 `request_cast(target)`，由基类驱动蓄力和形象阶段；在 `activate(target)` 实现真正生效的攻击。被动触发可以调用 `flash_release()`；持续飞剑不需要施法阶段。新增主动技能不要在 `tick` 直接调用 `activate`，否则会绕过可编辑的蓄力。

多人场景使用 `start_match(config)`。配置提供地图宽高、模式、种子和 2～8 个参战位置；位置包含角色、移动和队伍。`Fighter.fighter_id` 为唯一编号，`team_id` 为队伍；`opponent()` 返回最近敌人，`get_targets()` 返回所有敌人。多人结果读取 `winner_team` 和 `result`，旧 `winner` 仅用于双人兼容。

## 最快的方法：复制示例

`examples/wind_pulse` 是完整的第五角色：风行者。它增加脉冲范围伤害、击退和治疗，使用现有战场接口实现。

在 `data/roster.gd` 的 `CHARACTERS` 数组加入：

```gdscript
preload("res://examples/wind_pulse/wind_walker.tres"),
```

重新运行后即可在双方选角列表中使用。发行版需重新打包。

复制该示例或 `data/characters` 下的现有资源，修改唯一 `id`、名称、描述、图片、数值、默认移动和技能列表，即可建立另一个角色。角色资源共享的是配置，不要把生命、冷却或计时器存到资源中。

## 新技能

每个技能是一个挂有 `SkillBase` 子类脚本的 Node 场景。把场景放入角色 `skill_scenes` 数组。每局双方都会得到独立场景实例，即使选了相同角色，也不会共享冷却。

```gdscript
extends "res://scripts/skills/skill_base.gd"

@export var attack_range: float = 130.0
@export var damage_multiplier: float = 1.5

func tick(delta: float) -> void:
    super.tick(delta)
    if not can_act() or cooldown_remaining > 0.0:
        return
    var target = arena.opponent(fighter)
    if target != null and fighter.position.distance_to(target.position) <= attack_range:
        request_cast(target)

func activate(target) -> void:
    arena.apply_damage(fighter, target, fighter.definition.attack * damage_multiplier, skill_id)
    arena.emit_effect("slash", target.position, fighter.definition.theme_color)
    restart_cooldown()
```

给技能场景设置 `skill_id` 和 `cooldown`，再调整脚本导出的参数。持续技能可以在 `tick` 中实现轨道与命中间隔，参照 `orbit_blades.gd`；事件技能可覆盖 `on_damage_received`，参照 `guardian.gd`。

## 战场公共接口

| 调用 | 作用 |
| --- | --- |
| `opponent(fighter)` | 获取仍存活的对手，可能返回 null |
| `get_targets(fighter)` | 获取可攻击目标数组 |
| `apply_damage(source, target, amount, skill_id, allow_reaction=true, impulse=Vector2.ZERO)` | 伤害加入本步结算队列，统一处理护盾、死亡；非零击退向量同时触发逆时针旋转 |
| `heal(target, amount)` | 治疗，不超过最大生命 |
| `add_shield(target, amount, duration_seconds=4)` | 添加护盾，结束时间以战斗时钟计算 |
| `apply_status(source, target, id, duration_seconds, power)` | 添加状态；内置 `burn` 与 `slow` |
| `spawn_projectile(source, options)` | 生成投射物，自动处理移动、连续碰撞与命中 |
| `emit_effect(kind, position, color, extra={})` | 请求表现层播放效果，不改变战斗规则 |
| `rng` | 本场独立随机数发生器，随机行为应从这里取值 |

`burn` 的 power 是每秒伤害，每 0.5 秒结算；`slow` 的 power 是减速比例（0.35 表示减速 35%）。重复状态取较长剩余时长及较高强度。护盾有上限和有效期，不是永久生命。

投射物 options 支持 `position`、`velocity`、`radius`、`damage`、`lifetime`、`color`、`skill_id`，以及可选的 `blast_radius`、`status_id`、`status_duration`、`status_power`。火球实例展示完整用法。

表现层内置 `hit`、`shield`、`heal`、`burst`、`slash`、`dash`、`death`；可通过 `get_visuals()` 返回持续 `sword` 或 `ring` 表现。新增特效种类时，在 `scripts/ui/arena_board.gd` 对应分支补充绘制。

## 固定时间与伤害约束

- 技能使用 `tick(delta)` 的战斗时间，不使用系统时间、独立 Timer 或全局随机数；暂停与倍速会自然同步。
- 每个时间步先移动、检查技能和投射物，然后统一处理伤害与死亡。同一步双方致死可以判平局。
- 反击伤害用 `allow_reaction=false`，避免两个反击角色无限递归。
- 持续接触技能必须设置重复命中间隔，冲刺类技能需限制每次施法对同一目标的命中次数。
- 伤害、治疗和状态通过战场接口处理。视觉事件不应直接改变结果。
- 战场对投射物、伤害事件和表现队列设置了上限，错误技能不会无限堆积。

## 新移动策略

继承 `scripts/movement/movement_base.gd`，实现 `desired_velocity(delta)`；需要反弹时覆盖 `on_collision(normal)`。每名角色持有独立策略实例。

将新策略注册到 `BattleArena.MOVEMENTS`；在界面的 `MOVE_IDS`、`MOVE_NAMES` 中加入同一标识与中文名称，并扩展角色资源 `default_movement` 枚举。最后为新策略增加边界、碰撞与重开测试。

策略只输出期望速度。角色控制器统一处理实际位移、边界、碰撞、击退与冲刺覆盖。

## 验证

运行 `RunTests.cmd`。测试覆盖所有内置配对、同角色独立状态、固定种子重现、墙体与重叠、投射物、伤害与状态、死亡与超时规则、连续 100 局清理，以及第五角色扩展。

新增内容后还应打开游戏查看视觉效果；自动规则测试不能代替正式 PNG 接入后的美术验收。引擎、脚本或数值变化后，不承诺旧版本的种子仍产生完全相同的战局。
